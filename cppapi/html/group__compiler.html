Macro Definition Documentation

◆ BOND_COMPILER_ERROR_LIST

#define BOND_COMPILER_ERROR_LIST

An X-macro that lists every type of compiler error along with the format of its message.

To use it, define BOND_COMPILER_ERROR(type, format), expand BOND_COMPILER_ERROR_LIST and then undefine BOND_COMPILER_ERROR.

The format strings are not printf format strings. CompilerError::Print interprets the following directives, where an argument is arg0 unless the directive is preceded by a 0 or a 1 that selects arg0 or arg1 explicitly, e.g. "%1n":

  • %c: The text of the context Token.
  • %d: The argument as a signed integer.
  • %f: The file name of the argument, which is a Token.
  • %l: The line number of the argument, which is a Token.
  • %n: The argument, which is a ParseNode, pretty printed.
  • %s: The argument, which is a C-style string.
  • %t: The text of the argument, which is a Token.
  • %u: The argument as a Unicode code point, e.g. U+00E9.

◆ BOND_TOKEN_LIST

#define BOND_TOKEN_LIST

An X-macro that lists every type of Token.

To use it, define BOND_TOKEN_ITEM(item), expand BOND_TOKEN_LIST and then undefine BOND_TOKEN_ITEM. The argument of each item is the name of a Token::TokenType enumerator. INVALID is the type of a Token that could not be scanned, END is the type of the last Token of every TokenCollection, and NUM_TOKEN_TYPES is the number of types, not a valid type.

◆ AreAssignableTypes()

BOND_API bool Bond::AreAssignableTypes ( const TypeDescriptor & fromType,
const TypeDescriptor & toType )

Returns whether a value of one type can be assigned to an object of another type.

The destination type must be assignable, i.e. a non-const lvalue that is not an array. Pointers can be assigned if the source is null or a void pointer, if the destination is a void pointer, or if they point to the same type. Values can be assigned if their types are convertible.

◆ CombineOperandTypes()

BOND_API TypeDescriptor Bond::CombineOperandTypes ( const TypeDescriptor & typeA,
const TypeDescriptor & typeB )

Returns the type in which a binary operation on operands of the given types is performed, following C's usual arithmetic conversions.

If either operand is a pointer, the result is that pointer type as an rvalue. Otherwise, double takes precedence over float, which takes precedence over the promoted integer types, among which the wider one wins and unsigned wins when the widths are equal.

◆ IsLossyConversion()

BOND_API bool Bond::IsLossyConversion ( const TypeAndValue & fromTav,
const TypeDescriptor & toType )

Returns whether converting a numeric value to the given numeric type may lose data.

If the value is a compile-time constant, the conversion is lossy only if the value is not exactly representable by the destination type. Otherwise, it is lossy if the destination type cannot represent every value of the source type. Conversions involving non-numeric types are never reported as lossy.

Parameters
fromTavThe type and value being converted.
toTypeThe type to which the value is converted.
